# GptWorkBot 开发与使用说明

**简体中文** · [English](development.en.md)

给个人开发者使用的 Chrome Manifest V3 插件。沿用同一 ChatGPT 项目已有的独立 Work 会话与分工，用侧栏协调主管派发、成员回报和主管验收。无需 API Key，也没有独立付费后台。

## 安装

1. 在 Chrome 打开 `chrome://extensions`，开启“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择本工程的 **`dist` 文件夹**。
3. 刷新已打开的 ChatGPT 页面，固定并点击 **GptWorkBot** 图标，打开侧栏。
4. 进入现有 ChatGPT 项目或其中一个 Work 会话，侧栏点击“绑定会话”→“读取当前项目”。读取后会直接显示批量角色列表。
5. 勾选参与成员，选择主管，确认这些会话使用 Work 模式。点击“连接项目”后列表与选择会保留，继续点击批量加入。也可单独绑定会话地址。
6. 点击“连接协作 · 同步消息路由”。插件只约定消息格式与会话地址，沿用项目原有职责。
7. 在原 ChatGPT 主管会话下达目标，例如：“分析当前产品竞争力、对比竞品优劣势，再让营销基于分析成果制定宣传策略。请预先规划依赖链。”

`release/gptworkbot-1.1.0.zip` 是相同的构建包；解压后选择含 `manifest.json` 的文件夹即可。未发布到 Chrome 扩展商店。

推荐 Chrome 120 或更新版本。其他浏览器的侧栏 API 暂未适配。

## 中英文界面

侧栏右上角和“新增角色”表单均可选择中文／English，首次根据浏览器语言选择，后续记住偏好。状态、控件、系统提示和协作动态切换语言；用户提供的名称、职责、任务、成果及原生页面提示保留原文。语言设置独立保存，不修改团队和队列。

### 从 0.2.0 更新到 0.2.1

修复成员回报中原生文件引用的引号未转义导致 JSON 解析失败。保留现有 v2 团队和任务；重新加载扩展、刷新出错的 ChatGPT 会话并重开侧栏，点击“重新核对会话”即可恢复已有回报，无需重跑业务任务。下游仍须等待回传与验收。

### 更新到 0.2.0

本版采用协议 v2 和新的 `gptworkbot-state-v2` 存储，不迁移旧任务。旧存储保留，但不参与派发。重新加载扩展并刷新 ChatGPT 页面、重开侧栏后，需要重新读取项目、绑定团队并点击“连接协作”，同步新版协议。原 ChatGPT 会话可以继续使用。

若从 ZIP 安装，将新版解压覆盖原扩展目录后重新加载。刷新前保存输入框中的草稿。15 秒仍仅用于页面和发送控件准备，不限制 Work 执行时长。

## 更新到 1.1.0

本次发布继续使用协作协议 v2 和 gptworkbot-state-v2 存储。在同一扩展目录更新已有 0.2.x／1.0.0 安装时，团队与任务保留；重新加载扩展、刷新 ChatGPT 并重新核对会话。从 v1 安装升级时，需重新绑定并连接团队。自动化和真实会话验证范围见验证记录。

## 使用

主管回复有完整 v2 `json` 指令但队列没有任务时，更新本地扩展后重新加载、重开侧栏并点击“重新核对会话”。漏登记计划会显示原因；核对主管最新回复后点击“重新读取当前计划”，再检查草稿并“确认本轮”。恢复不重发原消息、不导入已登记来源、不补派历史计划。已有 v2 团队与成果保留，发布版本为 1.1.0。

竞争分析 → 完整成果回传主管 → 当前轮次验收 → 营销收到分析成果 → 制定宣传策略 → 主管验收汇总。见 [协议 v2](architecture.md)。

- **组织图**：主管居上，成员居下。名称旁的绿色点表示空闲，红色表示执行中，黄色表示需要进一步交互。灰色空心点表示页面未连接或状态过期；不会把未知状态显示成空闲。
- **每轮确认**是默认模式。主管提出的任务按轮显示，可展开、编辑、取消，再确认派发。新成员职责也可编辑。
- **自动协作**允许主管的新任务自动派发，默认最多 5 轮，随后暂停。已有待确认任务仍需你确认。设置可调整轮数及 1–4 个成员并发，默认 2 个。
- **按依赖协作**：主管预先规划整条任务链，用户确认整轮。前置任务完成、成果回传确认送达并通过当前轮次验收后，下游自动收到完整报告并启动；无依赖任务可并行。待确认时可调整前置任务，批准后固定。
- **修订闭环**：主管可指导已提交或待处理的原任务继续修订，轮次递增且历史保留；旧成果和迟到验收不会解锁后续。正常等待显示绿点，取消、失败或缺失输入显示黄点。
- **新成员**：主管可提出 `create` 操作。确认后，插件在当前项目打开后台标签页、选择 Work、发送首个任务；出现真实会话地址和用户消息回执后，才加入组织图，并同步主管的成员路由。
- **原生权限与额度**：需要批准、登录或额度处理时显示黄点，点击成员“打开会话”在 ChatGPT 内处理。插件不会替你批准原生操作。
- **草稿保护**：输入框已有用户内容时等待；明确未发送的完整插件草稿可以接续发送。发送到忙碌会话的消息排队。派发使用后台标签页，不主动切走你的主管会话。
- **恢复**：“重新核对会话”读取页面回执。“重试发送”恢复明确未发送的任务；“继续核对”让已收到任务的成员补充进展。发送不确定的任务只核对回执，不会自动重发。
- **停止与暂停**：“暂停”暂停后续消息；“请求停止”点击目标页面的原生停止按钮。生成停止不等于底层工具全部结束，需在原生会话检查。
- **完成与验收**：成员完成后标记“待主管验收”，主管 `accept` 或用户验收当前轮次；回传送达之前，提前用户验收也不会启动下游。

### 创建 Work 角色

1. 连接 ChatGPT 项目后，点击“团队组织”右侧的“新增角色”。项目标题旁的“＋”仍用于绑定已有会话。
2. 表单显示“加入当前项目”及项目名称。填写角色名称和职责，名称与职责会发送给该角色，原生 Work 会话也会使用此角色名称。创建始终使用此项目地址；填写期间切换项目会拒绝旧表单，避免加入其他项目。
3. 尚未绑定主管时，创建第一个 Work 主管并初始化协作方式；已有主管时，创建 Work 成员。成员可填写首个任务和验收条件，也可留空，只初始化职责并等待主管派发。
4. 点击“创建 Work 角色”直接提交到已确认队列，沿用成员并发限制。暂停期间显示“加入创建队列”，恢复后创建。连续点击或断连重试不会重复创建。
5. 插件在当前项目中打开新会话，尝试选择 Work 并发送初始化或首个任务。临时地址转为正式会话地址，并确认初始化消息回执后，新角色自动加入组织图，成员路由同步给主管。初始化结束后原生会话标题与角色名称同步。

如果页面提示需要手动选择 Work，打开该新会话选择 Work，再在侧栏对应任务点击“重试发送”。也可直接在 ChatGPT 项目中手动创建 Work 会话，再通过侧栏“绑定会话”加入团队。

通过主管创建仍然支持：绑定并连接主管后，在主管原会话发送例如“请新增质量检查角色，负责代码审查，首个任务检查当前实现并汇总问题”。默认确认模式下，先在侧栏检查该轮创建任务，再确认派发。

## 本地数据

绑定、依赖、任务、成果历史、输入快照、消息回执、页面观察状态与最近动态保存在扩展的 `chrome.storage.local`，存储键为 `gptworkbot-state-v2`。不会读取 Cookie、账号密码或 API Key，也不会把会话上传到第三方服务器。协议初始化、任务及成果回传会作为普通消息发送到你绑定的 ChatGPT 会话，因此这些内容会进入相应会话历史。

浏览器关闭时不会继续运行。卸载扩展或清理扩展存储会清除本地记录。重新加载同一扩展目录会保留原扩展 ID 和存储；移动目录可能改变 ID。默认只配置一组团队，存在未结束任务时不能切换项目。

## 开发

Node.js 20.13+（建议 Node.js 22 或 24）。

```sh
npm ci
npm run dev -- --port 5174
npm test
npm run package
npm run verify-package
```

预览地址：`http://127.0.0.1:5174/sidepanel.html`。普通网页预览带“演示预览”提示，仅用样例数据；真实扩展才连接 ChatGPT。

```text
src/core/       协议校验、状态、任务与回执
src/extension/ 后台调度、页面观察及 Work DOM 适配
src/panel/     组织图与侧栏交互
tests/         协议、DOM 与后台调度集成测试
dist/          可直接加载的扩展
release/       可分发的 ZIP
docs/          架构、验证记录与截图
```

## 验证与当前边界

已在登录后的 ChatGPT Work 项目进行独立测试会话的发送和代码块输出验证，并据真实页面实现隐藏节点过滤、ProseMirror 输入区和 Work 代码组件适配。0.2.0 共 13 个测试文件、245 项通过，类型检查、构建与安装包校验通过。自动化覆盖依赖链、修订轮次、快照重试、整批校验、串行及并发、草稿、回执恢复和新会话创建流程；具体结果见 [验证记录](verification.md)。

目前已能连接用户 Chrome 并验证原生 Work 标题编辑；工具安全策略禁止访问扩展管理页，无法代替用户重新加载插件。因此尚未在真实 Chrome 中完成“安装扩展→主管→两个成员→回传→验收”的完整联调。此项保留为安装后的验收清单，不把 DOM 验证或模拟后台测试称为完整实测。

ChatGPT 网页 DOM 不是稳定接口。界面更新、后台页休眠、流式连接中断和消息虚拟化都可能需要人工核对。当前适配中文/英文的主要控件；其他语言或未知页面显示交互／未知状态。协作仍受原账号 Work 能力、额度和模型输出格式约束。
